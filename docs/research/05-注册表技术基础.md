# 注册表技术基础(开发期技术依据)

> 调研日期:2026-10-12。事实以微软官方文档为准,来源见文末。

## 1. 架构:Hive 与根键映射

注册表是 Windows 内核(Configuration Manager)维护的层次数据库。Hive(配置单元)是一组键/子键/值的集合,系统启动或用户登录时由内核加载进内存;注册表 API 操作内存视图,内核经脏页回写 + 事务日志(.log/.blf/.regtrans-ms)异步落盘。程序看到的注册表与磁盘文件并非实时同步,离线解析 hive 文件读到的是上次刷新后的快照。

磁盘位置:

| 文件 | 位置 | 说明 |
|---|---|---|
| SAM、SECURITY、SOFTWARE、SYSTEM、DEFAULT | %SystemRoot%\System32\config\ | 无扩展名为主文件,.log 为事务日志,.sav 为安装阶段备份,.alt 仅 SYSTEM 有;NT 6.0+ 实际启用 .log1/.log2、.regtrans-ms(KTM 事务日志)、.blf |
| NTUSER.DAT | %UserProfile% | 对应 HKU\<SID> |
| UsrClass.dat | %LocalAppData%\Microsoft\Windows\ | 对应 HKU\<SID>_Classes(COM 类注册按用户存放) |

根键映射:

| 根键 | 本质 |
|---|---|
| HKCR | 合并视图:HKLM\SOFTWARE\Classes(系统级)+ HKCU\SOFTWARE\Classes(用户级,优先);写入 HKCR 实际落到 HKCU\Software\Classes |
| HKCU | 符号链接,指向 HKU\<当前用户 SID> |
| HKU\<SID>\Software\Classes | 符号链接,指向 HKU\<SID>_Classes |
| HKLM | 真实子键:HARDWARE(易失,内存生成)、SAM、SECURITY、SOFTWARE、SYSTEM |
| HKCC | 指向 HKLM\SYSTEM\CurrentControlSet\Hardware Profiles\Current |

编辑器要求:HKCR 显示为可切换的合并视图,标注真实写入位置(HKLM\Software\Classes / HKCU\Software\Classes);删除/重命名 HKCR 项时提示实际作用位置。

## 2. 命名规则与大小限制

| 项 | 限制 |
|---|---|
| 键名 | 大小写不敏感;可含除 `\` 外任意可打印字符;最长 255 字符(含从根键起的完整路径);不允许本地化 |
| 值名 | 最长 16,383 个 Unicode 字符(Win2000 为 260 ANSI);值名与数据可含反斜杠;每个键有一个无名默认值(regedit 显示为`(默认)`,.reg 中用 `@`) |
| 值数据 | 最新格式受可用内存限制,标准格式约 1 MB |
| 键树 | 深度 512 层;单次 API 调用最多创建 32 层;微软文档指引大于 2048 字节的数据存文件、注册表只存路径 |

## 3. 值类型全表

| 类型 | 用途 | 典型场景 |
|---|---|---|
| REG_SZ | Unicode 字符串 | 路径、名称 |
| REG_EXPAND_SZ | 含环境变量字符串(%PATH%) | 服务 ImagePath |
| REG_BINARY | 任意二进制 | BLOB、SDK 配置 |
| REG_DWORD | 32 位无符号整数(小端) | 开关、标志位 |
| REG_QWORD | 64 位整数 | 时间戳、大计数 |
| REG_MULTI_SZ | 双 NUL 结尾的字符串数组 | 服务 DependOnService |
| REG_NONE | 无类型数据 | 厂商自定义,编辑器按 hex 展示 |
| REG_LINK | Unicode 符号链接(内部) | HKCC 等链接,勿让用户改 |
| REG_RESOURCE_LIST / FULL_RESOURCE_DESCRIPTOR / RESOURCE_REQUIREMENTS_LIST | 硬件资源枚举(只读性质) | HKLM\HARDWARE |

REG_SZ/REG_EXPAND_SZ/REG_MULTI_SZ 读出的字符串可能未正确以 NUL 结尾,编辑器必须防御性处理。

## 4. WOW64:32/64 位注册表视图

- 64 位 Windows 上,32 位进程对 HKLM\SOFTWARE 等键的访问被透明重定向到物理位置 HKLM\SOFTWARE\Wow6432Node;ARM64 上 32 位 ARM 视图用 WowAA32Node。物理位置系统保留,应用不应直接访问 Wow6432Node。
- 共享键(Win7+,两个视图映射同一物理副本):HKLM\SOFTWARE\Classes 整体共享(其下仅 Classes\CLSID、Classes\Interface、Classes\DirectShow 等少数子键仍重定向);HKCU\Software 共享;Fonts、Policies、RegisteredApplications 等共享。
- 注册表反射(reflection)自 Windows 7 / Server 2008 R2 起已移除,两视图完全独立,无需处理同步。
- API 层用 KEY_WOW64_64KEY(0x0100)/ KEY_WOW64_32KEY(0x0200) 打开指定视图;默认视图跟随调用进程位数。
- Wow6432Node 下存在兼容符号链接(如 SOFTWARE\Wow6432Node\Classes → SOFTWARE\Classes\Wow6432Node)。

编辑器要求:① 提供 32/64 位视图切换(系统 regedit 经菜单切换),所有打开/枚举 API 统一传 KEY_WOW64_* 标志;② 编辑器编译为 32 位时,读 HKLM\SOFTWARE 会被重定向,须显式 KEY_WOW64_64KEY;③ 枚举与监控按视图分别注册;④ 展示 Wow6432Node 真实路径时标注"系统保留"。

## 5. 变更监控:RegNotifyChangeKeyValue 与 ETW

RegNotifyChangeKeyValue:

| 项 | 内容 |
|---|---|
| 参数 | bWatchSubtree(监控子树);过滤标志 REG_NOTIFY_CHANGE_NAME(子键增/删)、CHANGE_ATTRIBUTES、CHANGE_LAST_SET(值增删改)、CHANGE_SECURITY;Win8+ 有 REG_NOTIFY_THREAD_AGNOSTIC |
| 触发 | 单次触发,收到通知后必须重新调用 |
| 重命名 | 无重命名事件,表现为删除+创建 |
| 盲区 | 不感知 RegRestoreKey 造成的变更;远程句柄返回 ERROR_INVALID_HANDLE |
| 陷阱 | 同句柄不同参数重复调用静默失效;非持久线程池线程产生虚假信号;同参数重复调用泄漏资源 |

RegRenameKey(Vista+ 内核支持,已文档化)要求父键 KEY_CREATE_SUB_KEY + 整个子树 DELETE 权限。

机制事实:Process Monitor 用自带内核驱动(CmRegisterCallbackEx 注册表回调 + 文件系统 minifilter),非 ETW;ETW 提供程序 Microsoft-Windows-Kernel-Registry(Win8+)可用;Sysmon 注册表事件 12/13/14 基于同类内核回调。

监控设计:① 选中键用 RegNotifyChangeKeyValue(专职持久线程 + 循环重挂);② 全局活动流用 ETW Kernel-Registry(可拿到"哪个进程改了什么"与真正的 Delete/Rename/SetValue 事件);③ 事件量大,界面需过滤与节流。

## 6. KTM 现状

- RegCreateKeyTransacted / RegOpenKeyTransacted(Vista+/2008+)配合 CreateTransaction / CommitTransaction 实现原子修改;官方页面未标记弃用(页面更新于 2023-02,仅建议备份/恢复场景改用 VSS)。
- 只有显式以事务句柄打开的键操作在事务内,子键操作不自动继承。
- Project Zero 2024-2025 发现 KTM 注册表事务可产生非原子结果(缺陷 42451576);KTM 长期无功能演进,生态萎缩。

结论:撤销/安全写入不基于 KTM,用"修改前导出备份 + 内存快照 + 逐步应用";KTM 仅作实验特性。

## 7. 权限模型

- 每个键有安全描述符(ACL/所有者);权限检查基于键的 SD 而非打开句柄时的掩码;权限继承自父键。常见主体:SYSTEM、Administrators、Users/受限用户。
- SAM 与 SECURITY 的 ACL 只授予 SYSTEM(TrustedInstaller 更严),管理员组默认无读取权:管理员运行 regedit 也看不到内容,需以 SYSTEM 运行(如 PsExec -s)或显式改 ACL/夺所有权。SECURITY 同理(`reg save HKLM\SECURITY` 对管理员报拒绝访问)。
- 管理员(过滤令牌)写 HKLM 多数区域需提升;SeBackupPrivilege/SeRestorePrivilege 配合 REG_OPTION_BACKUP_RESTORE 可绕过常规 ACL 备份整棵键(RegSaveKey);ACCESS_SYSTEM_SECURITY 需 SeSecurityPrivilege。
- 远程注册表只见 HKLM/HKU 两个根键。

编辑器要求:① 区分"拒绝访问"三情形(ACL 拒绝/所有权异常/缺特权),给针对性提示与"以 SYSTEM 重启编辑器"选项(带风险确认);② 显示键 ACL 编辑器(等价 regedit 权限对话框)与所有者;③ Save Key / Load Hive 前检测 SeBackup/SeRestore 特权。

## 8. regf 格式与离线 hive

regf 文件结构:基块(header,魔数 "regf",含文件名、时间戳、校验)+ 一串 hive bin(hbin)+ cell;键节点(nk)、值(vk)、子键列表(li/lf/ri 等)、安全描述符(sk)cell,另有 free cell 与小孔压缩。格式自 NT 3.1 起沿用至 Win11,结构未变。

挂载 API:

| API | 特性 |
|---|---|
| RegLoadKey / RegUnLoadKey | 需 SeBackup/SeRestore 特权,挂到 HKLM/HKU 下;regedit"加载配置单元"即此 |
| RegLoadAppKey(Vista+) | 加载为私有根键,不需管理员,不进全局命名空间 |
| Offline Registry Library(Win 8.1+) | OROpenHive 等,应用直接读离线 hive |

开源解析库:regipy(Python,活跃,支持遍历/恢复已删项/提取,另有 Rust 版 regipy-rs alpha)、python-registry(yarp)、C# Registry 库、libregf(数字取证常用)。

结论:① "加载配置单元"对齐 regedit(在线挂载,可编辑);② 只读打开 hive 文件内置自研 regf 解析器(或 libregf 风格实现),支持离线解析 NTUSER.DAT/UsrClass.dat/SOFTWARE、展示已删除未覆盖记录、导出 .reg,可支撑取证与 PE 修复/系统迁移场景。regf 存在脏数据与损坏文件,解析器必须容错。

## 9. .reg 文件格式

微软无单一规范页,以下为 regedit 5.00 格式的通行规范:

- 文件头第一行 `Windows Registry Editor Version 5.00`,编码 UTF-16LE 带 BOM(FF FE);Win9x 兼容旧格式用 `REGEDIT4` + ANSI。行间空行分隔,`;` 开头为注释。
- 键路径 `[HKEY_LOCAL_MACHINE\Software\...]`,方括号包裹;根键写缩写 HKLM/HKCU/HKCR/HKU/HKCC 或全名,两种写法。
- 值语法 `"值名"=类型:数据`;默认值 `@="..."`;删除键 `[-HKEY_LOCAL_MACHINE\Software\Key]`;删除值 `"Value"=-`。
- 转义:`\\` 一个反斜杠,`\"` 引号,`\n` 换行;字符串内不能有未转义的 NUL。

| .reg 写法 | 类型 |
|---|---|
| `"x"="abc"` | REG_SZ |
| `dword:00000001`(8 位十六进制) | REG_DWORD |
| `hex:` | REG_BINARY(裸二进制) |
| `hex(0):` / `hex(1):` | REG_NONE / REG_SZ |
| `hex(2):` / `hex(7):` | REG_EXPAND_SZ / REG_MULTI_SZ |
| `hex(4):` / `hex(5):` | REG_DWORD_BIG_ENDIAN / REG_LINK |
| `hex(b):` | REG_QWORD |
| `hex(8)` ~ `hex(a):` | 资源类型 |

hex(2)/hex(7) 数据为逗号分隔的字节流,UTF-16LE,NUL 结尾;REG_MULTI_SZ 双 NUL 结尾。

编辑器要求:导入采用"先全部校验再应用"或逐条回滚;导出正确处理引号/反斜杠/换行/非 BMP 字符的转义;导入 `[-HKEY...]` 前弹高危确认。

## 10. 注册表虚拟化与 AppContainer

- Registry Virtualization(Vista+):标准用户对 HKLM\Software(仅此子树,排除 Classes、Microsoft\Windows、Microsoft\Windows NT)的失败写操作被重定向到 HKU\<SID>_Classes\VirtualStore\Machine\Software;读取时呈现 VirtualStore 优先于全局的合并视图。
- 仅对 32 位交互进程生效;64 位进程、服务、模拟身份、内核驱动、带 requestedExecutionLevel 清单的进程不虚拟化。可用 reg flags(REG_KEY_DONT_VIRTUALIZE / DONT_SILENT_FAIL / RECURSE_FLAG)按键控制。
- 编辑器要求:自身用 asInvoker 清单 + 手动提升;用户态监控只看到 VirtualStore 写入,ETW/驱动层监控不受影响;界面提示"该项在 VirtualStore 存在用户级副本"。
- AppContainer(UWP/低完整性)通过 ALL APPLICATION PACKAGES SID 的 ACL 限制键访问,不产生虚拟副本;编辑器以正常完整性运行不受影响,分析 UWP 应用数据时需检查 AppContainer ACL。

## 11. 高危键清单

误改以下键可致系统无法启动或软件损坏:

| 区域 | 风险 |
|---|---|
| HKLM\SYSTEM\CurrentControlSet\Services | 服务/驱动的 Start、ImagePath、Group 改错导致服务失效或 0x7B 蓝屏;其下有 SafeBoot 子键 |
| HKLM\SYSTEM\Select / ControlSet001/002 | CurrentControlSet 是指向 Select 所选 ControlSet 的链接,直接改 ControlSet 结构风险极大 |
| HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon | Userinit/Shell/UserManager 改错导致无法登录 |
| CurrentVersion\ProfileList | ProfilesDirectory/SID 路径改错导致登录即坏配置 |
| Session Manager | BootExecute、PendingFileRenameOperations |
| HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run / RunOnce | 自启动项 |
| IFEO(Image File Execution Options) | 劫持高发区 |
| HKCR\Classes 批量改动 | 文件关联与 exe 启动 |
| Control\TimeZoneInformation、键盘布局 | 登录前生效项 |

内置保护机制(产品差异化):① 危险区域分级标注(红=启动关键/身份验证,黄=服务/自启动),删除与批量导入前强制确认;② 每次修改自动快照(键级导出 .reg + 修改日志,一键撤销/时间线回滚);③ 只读模式与管理员模式分离启动;④ .reg 导入 dry-run 预览差异;⑤ 检测到 IFEO/Winlogon/Services 敏感值变更时提示(可对接 Defender);⑥ 符号链接/HKCR 合并视图/Wow6432Node 显示真实写入位置。
