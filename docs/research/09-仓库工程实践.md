# 09 仓库工程实践调研

调研对象:Files、DevToys、PowerToys、Notepads、github/gitignore、dotnet/roslyn。所有文件内容均抓取自真实仓库 main/master 分支(2026-10)。

## 1. README 结构

### 四个项目的节顺序

| 项目 | 节顺序(自上而下) |
| --- | --- |
| Files | hero 图 → badges → 一句话描述 → 安装与运行(Store/经典安装器) → 从源码构建 → 参与贡献 → 截图 |
| DevToys | logo → 标题 → badges → 一句话描述 → 下载(Store/winget/choco) → 特性+截图 → 参与贡献 → 致谢 |
| PowerToys | hero 图 → 标题 → 描述 → 导航链接(安装/文档/博客/发行说明) → 工具列表 → 安装(折叠块) → What's new → Roadmap → 社区 → Contributing → 行为准则 → 隐私 |
| Notepads | logo → 标题 → 描述 → badges → 是什么/为什么 → 特性列表 → 截图 → 快捷键 → 平台限制 → 下载(Store+winget) → Changelog(链 Releases) → 隐私声明 → Contributing → 依赖 → 致谢 |

共同骨架:**图标/标题 → 一句话描述 → 截图或特性 → 安装 → 构建 → 贡献 → 许可/隐私**。安装永远在构建之前;小项目(Notepads)直接把 changelog 链到 GitHub Releases,不单独维护文件。

### badge 组合(shields.io,真实取用)

| 项目 | badge |
| --- | --- |
| Notepads | Store 下载(静态 badge)、`img.shields.io/github/release`(最新版本)、平台 `Windows \| UWP`(静态)、Discord |
| Files | CI 状态 `github.com/<owner>/<repo>/actions/workflows/ci.yml/badge.svg`(GitHub 官方 workflow badge)、Crowdin 翻译进度、Discord |
| DevToys | 构建状态 workflow badge、Discord、下载量、许可证 |
| PowerToys | 不用 badge,hero 大图替代 |

常用组合:**workflow 构建状态 + 最新 Release 版本 + 许可证 + 平台(Windows/WinUI3)+ 商店或下载入口**。版本 badge 用 `img.shields.io/github/v/release/<owner>/<repo>`;构建状态用 GitHub 官方 `actions/workflows/<name>/badge.svg`,不必走 shields。

### 开发中项目(WIP)的标注方式

- 版本号停在 0.x(Notepads 早期、PowerToys 至今 v0.x);README 不写"stable"。
- Files 在安装节标注 Preview/渠道区分(stable/preview 分支发不同包)。
- PowerToys 设 Roadmap 节 + milestone 链接。
- 通用做法:静态 shields badge(`status-WIP` / `status-actively developing`)+ README 描述里写"早期开发中"。无官方规范,以上为同类项目实际做法。

## 2. .gitignore

| 事实 | 结论 |
| --- | --- |
| github/gitignore 的 `VisualStudio.gitignore` 仍是 VS/.NET 项目的权威模板 | GitHub 官方模板仓库唯一 VS 模板;无 WinUI 专用官方模板 |
| 现状 | 432 行(347 loc),7.34 KB;最近提交 2026-10-02(回退 *.snk)、2026-09-04(#4839);持续维护 |
| 已覆盖 WinUI 所需 | `.vs/`、`[Bb]in/`、`[Oo]bj/`、`*.pfx`、`AppPackages/`、`BundleArtifacts/`、`Package.StoreAssociation.xml`、`_pkginfo.txt`、`*.appx`、`*.appxbundle`、`*.appxupload`、`*.msix`、`*.snupkg`、`*.binlog`、`Generated\ Files/` |
| 缺口(需自补) | `*.msixupload`、`*.msixbundle`、`*.appxsym`、`*.appinstaller`(如本地生成)、`**/Properties/launchSettings.json`、`.artifacts/`已含 |
| 真实仓库先例 | Files `.gitignore` = VisualStudio.gitignore 底版 + 自定义段(自定义构建产物、`*.pfx`、`*.sln.iml`、`.idea/`);DevToys 同样基于 VS 模板 |

结论:**以 VisualStudio.gitignore 全文为基底,追加一小段 WinUI/MSIX 补充**。生成的测试证书 `*.pfx` 已被覆盖,但注意 VS 的 `Package.pfx` 若在 `AppPackages` 目录外也会被 `*.pfx` 命中,无需额外规则。

## 3. .editorconfig

| 要点 | 事实 |
| --- | --- |
| 官方推荐 | .NET 团队推荐用 EditorConfig 同时承载编辑器风格 + 分析器规则严重级;Visual Studio 有内置 item 模板;ruleset 已废弃 |
| 权威模板 | dotnet/roslyn 的 `.editorconfig`(root=true)` |
| Roslyn 模板缩进规则 | `[*]` indent_style=space;`[*.{cs,csx,vb,vbx}]` indent_size=4、utf-8-bom;csproj/props/resx/config 等 XML 类 indent_size=2;JSON/ps1/sh 2 |
| C# 风格 | 命名规则(实例字段 `_camelCase`、静态字段 `s_`、PascalCase 成员)、`var` 偏好、大括号新行、`csharp_prefer_braces` |
| XAML | Roslyn 模板无 `[*.xaml]` 节;Files 用 XamlStyler.Console(xstyler)在 CI 做 XAML 格式检查,独立 `Settings.XamlStyler` 配置,惯例 XAML 2 空格缩进 |

做法:**root=true + Roslyn 模板精简版 + 新增 `[*.xaml]` indent_size=2**。分析器严重级可只挑少数(`dotnet_diagnostic.CAxxxx.severity`),不必整抄 Roslyn 的规则。

## 4. Issue / PR 模板

### yaml forms 语法现状

- 官方 form schema 支持 6 种元素:`markdown`、`textarea`、`input`、`dropdown`、`checkboxes`、`upload`;文档仍标注 "public preview"。
- `textarea`/`input` 支持 `validations.required`、`min_length`;`dropdown` 支持 `multiple`、`options`、`default`;`upload` 支持 `accept` 扩展名过滤(文本 25MB、图片 10MB、视频 100MB)。
- 目录:`.github/ISSUE_TEMPLATE/*.yml` + `config.yml`。

### 两个真实项目的字段设计

| 字段 | Files bug_report.yml | DevToys bug_report.yml |
| --- | --- | --- |
| 先查重提示 | markdown(TIP 块,先搜索已有 issue) | markdown(点赞表示同遇) |
| 描述 | textarea,必填 | Current behavior textarea,必填 |
| 复现步骤 | textarea(1/2/3 占位),必填 | textarea,**选填** |
| 期望行为 | (并入描述) | textarea,必填 |
| 版本号 | Files 版本 input,必填 | DevToys 版本 input,必填 |
| 系统版本 | Windows 版本 input,必填 | 平台 dropdown 多选 |
| 日志 | markdown 指引日志位置 + `upload` 字段(accept `.log`),必填 | textarea 粘贴/拖拽日志 |
| 其他 | — | Screenshots、Workaround |
| labels | `type: 'Bug'` | `labels: bug, untriaged` |

结论:bug 报告**带版本号 + 复现步骤 + 日志**是两个项目的共同选择;版本号都设为必填。DevToys 另拆 `feature_request.yml`、`enhancement_request.yml`;Files 只有 bug 模板。

### config.yml 留讨论区入口

```yaml
blank_issues_enabled: false
contact_links:
  - name: Questions
    url: https://github.com/<owner>/<repo>/discussions
    about: For general questions, visit GitHub discussions
```

(DevToys 实际文件,原文如此。)

## 5. CI / CD

### 官方方案(learn.microsoft.com,ci-for-winui3,2026-08-30 更新)

| 决策点 | 官方结论 |
| --- | --- |
| runner | `windows-latest` |
| 工具链 | `actions/setup-dotnet@v4`(设目标 .NET 版本)+ `microsoft/setup-msbuild@v2` |
| 构建方式 | packaged WinUI 用 **msbuild**(`/t:Restore` 再 `/t:Build` + 打包参数);unpackaged 才用 `dotnet publish` |
| 打包参数 | `/p:GenerateAppxPackageOnBuild=true`、`/p:AppxPackageDir`、`/p:UapAppxPackageBuildMode=SideloadOnly|StoreUpload`、`/p:AppxBundle=Never|Always`、`/p:AppxBundlePlatforms="x86\|x64"` |
| .msixupload | `UapAppxPackageBuildMode=StoreUpload` 产出;`Platform=x86` 选触发打包的配置 |
| 签名 | pfx 转 Base64 存 secret `BASE64_ENCODED_PFX`,构建时解码写盘再 `PackageCertificateKeyFile=`,结束删除;上 Store 则 `AppxPackageSigningEnabled=false`(商店代签) |
| Windows App SDK runtime | 构建/打包**不需要**装 runtime;只有要在 runner 上安装运行 app(如 UI 测试)才需要 |

### 真实仓库先例

| 仓库 | 文件 | 要点 |
| --- | --- | --- |
| Files | `.github/workflows/ci.yml` | `windows-2025-vs2026`;matrix Debug/Release × x64/arm64;setup-msbuild@v3 + setup-dotnet@v5(global.json 锁版本);XamlStyler 检查 XAML 格式;测试腿现场生成自签 pfx 打包 |
| Files | `.github/workflows/cd-sideload-stable.yml` | 触发 `workflow_dispatch`(手动),非 tag;逐架构构建 + 合并 msixbundle + Azure Trusted Signing + 上传分发 |
| DevToys | `.github/workflows/ci.yml` | Nuke 构建,PR 触发,三平台矩阵(windows-latest/ubuntu/macos),NuGet 缓存 |
| 官方文档 | Store 打包 workflow | msbuild StoreUpload 单次产出 x86\|x64 `.msixupload`,upload-artifact 上传 |

### runner 上的已知问题与解法

| 问题 | 解法 |
| --- | --- |
| 单项目 MSIX 迁移后 CI 打包失败(WindowsAppSDK #1835) | 用 msbuild + 打包 MSBuild 属性(GenerateAppxPackageOnBuild 等),而非 dotnet build |
| runner 上安装打包后的 app 报 0x80073CF3(runtime 低于 MinVersion) | 按 `Directory.Packages.props` 里的精确 SDK 版本下载 `windowsappruntimeinstall-x64.exe` 安装(Files 做法;aka.ms 的 latest 可能滞后) |
| 用户机器无 Windows App Runtime | 项目设 `WindowsAppSDKSelfContained=true` 自包含打包,或分发 runtime 安装器 |
| 证书入库 | 不入库;pfx Base64 存 Actions secret(官方)或 Trusted Signing(Files) |

### tag → Release 附 .msixupload 的组合

官方文档无 tag 发版完整 workflow;先例组合:官方 StoreUpload workflow(产出 msixupload)+ `softprops/action-gh-release@v3`(`if: github.ref_type == 'tag'`,files 传包路径;tag 已有 release 时更新 assets)。`on: push: tags: 'v*'` 触发。Store 上架另有官方 `msstore` CLI GitHub Actions 文档。

## 6. 版本与变更日志

| 主题 | 事实 |
| --- | --- |
| SemVer 2.0.0 | 第 4 条:0.y.z 用于初始开发,任何内容可变,API 不视为稳定;1.0.0 起才算公共稳定 |
| 0.x 实例 | PowerToys 至今 v0.x,用 milestone 管理下一版 |
| Keep a Changelog | 现行版本 1.1.0;`CHANGELOG.md` 顶部常驻 `Unreleased` 节;分类 Added / Changed / Deprecated / Removed / Fixed / Security;配合 SemVer 声明 |
| 个人项目惯例 | Notepads 不维护 CHANGELOG 文件,Changelog 节直链 GitHub Releases;版本 tag 命名 `v1.x.x` |

结论:0.x 阶段用 SemVer + tag `v0.x.y`;CHANGELOG 用 Keep a Changelog 1.1.0 格式,早期可接受 Releases 代餐,但文件成本极低,建议直接建。

## 7. 仓库设置

| 项 | 惯例/事实 |
| --- | --- |
| description | 一句话英文,说明"是什么+平台",如 Files: "A modern file manager that helps users organize their files and folders." |
| topics | 小写、连字符;参考词:`winui3`、`windows-app-sdk`、`registry-editor`、`regedit`、`windows`、`dotnet`、`csharp`、`fluent-design`、`msix`、`file-registry` |
| 默认分支 | GitHub 自 2020-10 起新仓库默认 `main` |
| 分支保护 | 功能权限:公开仓库 GitHub Free 可用;**私有仓库需 Pro/Team+**。可选项:require PR reviews、require status checks、禁止 force push(默认已禁)、禁止删除、线性历史 |
| 个人项目建议 | 私有阶段(自己是唯一提交者):不开 PR review 类保护,收益为零;转公开后对 main 开 require status checks + 保持禁 force push 即可,不必开 review |
