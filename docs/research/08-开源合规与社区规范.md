# 08 开源合规与社区规范调研

调研日期:2026-10-13。方法:直接核查各仓库根目录文件列表与 LICENSE 原文,辅以 GitHub Docs、choosealicense.com、Contributor Covenant 官网、Microsoft Store 政策原文。未凭记忆填写任何版本号。

## 1. 许可证

| 项目 | 许可证 | LICENSE 文件名 | 版权行(实测原文) |
|---|---|---|---|
| Files (files-community) | MIT + MPL-2.0 双许可 | LICENSE-MIT + LICENSE-MPL | `Copyright (c) 2018 - present Files Community` |
| DevToys | MIT | LICENSE.md | `Copyright (c) 2021`(仅年份,无姓名) |
| PowerToys (Microsoft) | MIT | LICENSE | `Copyright (c) Microsoft Corporation. All rights reserved.` |
| Notepads (0x7c13,中国作者) | MIT | LICENSE.txt | `Copyright (c) 2019-2024 Jackie (Jiaqi) Liu` |
| TotalRegistry (zodiacon) | MIT | LICENSE | `Copyright (c) 2021 Pavel Yosifovich` |
| Windows Terminal (Microsoft) | MIT | LICENSE | — |
| TranslucentTB | GPL-3.0 | LICENSE.md | FSF 标准全文 |

结论:

- 抽样 7 个现代 Windows 桌面工具,6 个 MIT(约 86%);唯一 GPL-3.0 为 TranslucentTB。
- 微软开源政策明确:无特殊理由默认用 MIT。
- MIT 是强 copyleft 之外商店分发最省事的选项;GPL 与商店统一许可条款存在兼容争议(SFC 2022 分析),免费 MIT 应用无此问题。
- Microsoft Store 政策(v7.20,2026-10-22 生效)全文无任何开源许可证要求。相关条款:11.2(产品内容须自创或已获授权)、10.5.1(Win32/桌桥产品必须提供隐私政策 URL)。Files、DevToys、Notepads 均为开源 + 上架商店的实例。
- 版权行惯例(choosealicense.com MIT 模板):`Copyright (c) [year] [fullname]`。实测四种写法:组织名(Files/Microsoft)、仅年份(DevToys)、英文名+年份区间(Notepads、TotalRegistry)。中国作者 Notepads 用英文名。

## 2. CONTRIBUTING.md

| 项目 | 位置 | 篇幅 | 结构 |
|---|---|---|---|
| DevToys | 根目录 | 163 行 / 9.7 KB | 贡献入口(bug / feature 模板链接、PR、i18n)→ 分平台构建步骤(前置依赖、初始化、构建运行调试)→ Crowdin 翻译指引 |
| Files | .github/ | 短 | DO/DON'T 清单风格:先开 issue 说明意图、一个 Issue 对应一个 PR 并互链、遵循编码规范;构建细节放外部文档站 |
| PowerToys | 根目录 + doc/devdocs/ | 长 | 贡献类型、CLA 要求、开发者文档链接(环境搭建/编译) |
| Notepads | 根目录 | 短 | 个人项目;贡献入口 + 赞助链接 |
| TranslucentTB | 根目录 | 短 | 联系渠道(Discord/GitHub)、范围声明 |

结论:个人/小项目 CONTRIBUTING.md 通常 50–150 行,核心四块——贡献方式、开发环境与构建步骤、issue/PR 规范、引用行为准则。无 CLA 要求。

## 3. CODE_OF_CONDUCT.md

| 项目 | 采用 |
|---|---|
| PowerToys、Windows Terminal | Microsoft Open Source Code of Conduct(微软内部 CSS 版) |
| Notepads | Contributor Covenant(全文复制) |
| Files | Citizen Code of Conduct |
| DevToys | 自有 CODE-OF-CONDUCT.md |

Contributor Covenant 版本(官网确认):

- 当前版本 3.0,2025-07-28 发布;官网 FAQ 将 1.0–2.1 全部列为"previous versions"。
- 2.1 为上一代使用最广的存量版本,大量项目仍在用。
- 采用方式:复制全文到 CODE_OF_CONDUCT.md,补充项目联系方式(3.0 正文的报告渠道需项目自行填写)。

## 4. SECURITY.md

- GitHub 私有漏洞报告(Private Vulnerability Reporting, PVR)与 SECURITY.md 是两个独立机制:SECURITY.md 是展示在仓库侧栏 "Security policy" 的政策文档;PVR 是仓库设置中开启的私密报告通道。官方文档原文:"Private vulnerability reporting is separate from a repository's SECURITY.md file."
- GitHub 官方博客维护者安全清单:加 SECURITY.md、开启 PVR、secret scanning、Dependabot。
- DevToys SECURITY.md(个人团队范本):支持版本声明 → 首选 GitHub "Report a vulnerability" 按钮 → 备用邮箱 → 72 小时响应承诺 → 协调披露流程 → 范围内/外清单。
- PowerToys SECURITY.md:微软模板,统一指向 MSRC,不适用个人项目。

## 5. CLA / DCO

| 项目 | CLA | DCO |
|---|---|---|
| PowerToys | 有(微软 CLA) | 无 |
| DevToys、Files、Notepads、TotalRegistry、TranslucentTB | 无 | 无 |

结论:CLA 用于企业保留改许可与诉讼能力,DCO 是逐提交签核(`Signed-off-by`)。两者对个人小项目均无必要;同类个人项目实测全部不用。

## 6. 中英双语

| 案例 | 做法 |
|---|---|
| Notepads(中国作者 Jackie Liu) | README 纯英文;LICENSE 用英文名;中文仅出现在应用内本地化 |
| LobeChat 等中国团队项目 | README.md(英)为主文件 + README.zh-CN.md 互链 |
| DeepSeek-R1 | README 英文为主,后补中文版并声明同步 |

GitHub 社区讨论结论:多语言 README 用独立文件(`README.zh-CN.md` 等),在主文件顶部放语言切换链接;不支持单文件内自动切换。社区文件(CONTRIBUTING / CoC / SECURITY)业界默认英文。

## 本项目推荐方案

ModernRegedit:个人项目(WinUI 3 + .NET 10),计划开源 + 上架 Microsoft Store,目标国际用户。

**许可证:MIT。**

理由:

1. 同类主流:抽样 7 个项目 6 个 MIT,微软开源政策默认也是 MIT。
2. 与 Store 分发、winget、他人二次分发零冲突;GPL-3.0 带来商店条款与商用捆绑顾虑,收益为零。
3. 版权保留在作者,商店版本可自由定价与闭源附加(如需)。

版权行建议:`Copyright (c) 2026 HuaJiahao`(英文拼写,与 Notepads 用英文名的先例一致;也可用 GitHub 用户名)。

**要创建的文件清单:**

| # | 文件 | 位置 | 要点 |
|---|---|---|---|
| 1 | `LICENSE` | 根目录 | MIT 全文,版权行 `Copyright (c) 2026 HuaJiahao`;命名用 `LICENSE`(无扩展名,GitHub 自动识别) |
| 2 | `README.md` | 根目录 | 英文为主;徽章(Store/License/build)、简介+截图、安装(Store/winget)、构建步骤、Contributing/Security/Privacy 链接;顶部放 `English | 简体中文` 切换;可选 `README.zh-CN.md` 互链 |
| 3 | `CONTRIBUTING.md` | .github/ | 50–100 行:贡献方式(bug 模板/feature 模板/PR)、开发环境(Windows 11、VS 2022 或 VS Code、.NET 10 SDK、Windows App SDK)、`dotnet build` 构建步骤、PR 规范(一个 PR 对应一个 issue、分支命名)、引用 CoC。不设 CLA/DCO |
| 4 | `CODE_OF_CONDUCT.md` | .github/ | Contributor Covenant 3.0 全文,报告渠道填个人邮箱;个人项目可加一句"维护者即唯一协调人" |
| 5 | `SECURITY.md` | .github/ 或根目录 | 短:支持版本(仅最新版)→ 首选 GitHub "Report a vulnerability" → 备用邮箱 → 72h 响应 → 范围内/外;同时在仓库 Settings → Code security 开启 Private vulnerability reporting(两者独立,都要做) |
| 6 | `PRIVACY.md` | 根目录(建议) | Store 政策 10.5.1 要求 Win32 产品提供隐私政策 URL;注册表编辑器若不收集数据,写明"不收集、不上传"并披露任何遥测即可;上架时填入 Partner Center |
| 7 | `THIRD-PARTY-NOTICES.md` | 根目录(引入第三方库后) | 列出依赖及其许可证(参照 DevToys 同名文件) |

不做:CLA、DCO、SUPPORT.md(个人项目 GitHub Issues 即支持渠道,可并入 README)。
