# 开发工作流

单个功能的标准开发循环、部署与验证方法。环境与依赖版本见 [开发环境.md](开发环境.md)，里程碑范围见 [PLAN.md](../PLAN.md) §5。

## 功能循环

1. 从 PLAN.md 当前里程碑取一个功能（或用户指定的功能），一个功能一个分支内改动。
2. 写代码，`dotnet build src/ModernRegedit/ModernRegedit.csproj -c Debug -p:Platform=x64` 必须通过。
3. 部署到本机（见下节）。
4. 冒烟：启动应用，确认进程存活。
5. 功能验证：用 UI 自动化（UIA）走查目标交互（见下节）。
6. `git commit`——一个功能一个提交，Conventional Commits。
7. 里程碑全部功能完成后：PLAN.md 表格打勾、CHANGELOG.md 追加条目、push、`gh run watch` 确认 CI 绿。

## 部署与启动（PowerShell）

```powershell
# 注册（开发者模式，免签名）
Add-AppxPackage -Register 'D:\Code\ModernRegedit\src\ModernRegedit\bin\x64\Debug\net10.0-windows10.0.26100\AppxManifest.xml' -ForceApplicationShutdown

# 启动
Start-Process 'shell:AppsFolder\4E406B62.ModernRegedit_dkcj7grfjrc2g!App'

# 判活 / 关闭
Get-Process ModernRegedit
Stop-Process -Name ModernRegedit
```

改包身份（Identity）后 PFN 会变，需与 [商店发布信息.md](商店发布信息.md) 同步；旧包用 `Get-AppxPackage -Name ModernRegedit | Remove-AppxPackage` 清理。

## UI 自动化验证（UIA）

用 PowerShell + `System.Windows.Automation` 写一次性脚本，放在仓库外的临时目录（**不提交**）。脚本含中文注释时用 `pwsh` 运行（Windows PowerShell 5.1 按 ANSI 读 UTF-8 会解析错乱）。要点：

- 先最大化窗口（`user32!ShowWindow`，SW_MAXIMIZE=3），减少虚拟化导致的元素缺失。
- `TreeViewItem` 的 UIA `Name` 是 CLR 类型名（如 `ModernRegedit.ViewModels.RegistryKeyNode`），真实标签在其内层 `Text` 元素上——定位节点取内层文本。
- 视口外的树节点未物化，UIA 找不到：反复对最后可见项 `ScrollItemPattern.ScrollIntoView()` 强制实现，再重查。
- 文本框输入不要用 `ValuePattern.SetValue`（不触发 TextChanged，TwoWay 绑定不更新），也不要逐键 SendKeys（中文 IME 会拦截成组合态）：用 `Set-Clipboard` + `^v` 粘贴。
- 键盘焦点与选中是两回事：`SelectionItemPattern.Select()` 不移动焦点，触发 KeyDown 类交互前先 `SetFocus()`；焦点失败时可退回鼠标双击（`mouse_event` 两次）。
- 结束时检查进程存活（挂死排查见下节），并 `Stop-Process` 清理。

## 崩溃与挂死排查

查事件日志 Application：

- `MoAppHang` / Application Hang 1002 → UI 线程冻结（M0 曾因大键同步枚举 + N+1 计数查询触发，已修复；新增枚举逻辑必须走后台线程）。
- `.NET Runtime` 1026 / `c0000409` → 托管异常 fail-fast，消息里有异常类型与堆栈。

## 发布包（PowerShell，在仓库根）

```powershell
dotnet build -c Release /p:UapAppxPackageBuildMode=SideloadOnly /p:AppxBundle=Never   # sideload 包 → AppPackages/
dotnet build -c Release /p:UapAppxPackageBuildMode=StoreUpload                        # 商店包 .msixupload
```

## CI

`.github/workflows/ci.yml`：windows-latest + setup-dotnet 10.0.x + setup-msbuild，直接构建 csproj（slnx 无 x64 解决方案配置）。推送后 `gh run watch <id>` 看结果。
